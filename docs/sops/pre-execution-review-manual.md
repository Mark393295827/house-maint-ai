# 前置审查型 OKR 刻意练习手册

专为追求极致杠杆率和系统自动化的开发与创业项目设计。

## 核心法则：前置审查网关 (The Pre-Execution Gateway)

任何任务在转化为 OKR 并进入执行阶段前，**必须 100% 通过“框架先决条件审查”（5W2H 动机穿透 + MECE 边界锁死）**。未通过审查的冲动型想法，一律驳回，拒绝执行。

为了量化这种高杠杆执行标准，我们将系统资源回报率定义为：
$$System\ ROI = \frac{\Delta Business\ Impact}{\sum (API\ Latency + Human\ Meta\-work)}$$

---

## 审查维度与达标标准 (Top 1% 的回答特征)

| 维度 | 强制穿透提问 (5W2H + MECE) | 达标标准 |
| :--- | :--- | :--- |
| **Why (杠杆核实)** | 这件事是否具备 10X 增长潜力或极大的降本增效空间？ | **拒绝线性增长。** 必须明确指出技术降维套利的破局点（如替代了哪部分高昂的人工摩擦力）。 |
| **What (MVP 定义)** | 剥离所有伪需求后，最小可行性交付物是什么？ | **拒绝“宏大系统规划”。** 必须是一个在 4-8 小时内能跑通的最简代码脚本或核心数据表格。 |
| **Who & Where (系统载体)** | 哪些部分由 Agent 自动化执行？哪些由人工兜底？部署在哪？ | **明确系统边界。** 切分大模型原生推理域与传统规则拦截域。 |
| **How & How much (微观事实)** | 核心技术路径是什么？容错率和 API / 资金成本底线是多少？ | **必须有具体数字锚定。** 拒绝抽象描述，直接量化延迟、Token 消耗或资金门槛。 |

## OKR 极简重构框架

当任务通过前置审查后，按“战略层 $\rightarrow$ 系统层 $\rightarrow$ 执行层”的 MECE 结构将其转化为 OKR。

### 1. Objective (目标)
*   **聚焦**：战略层与高杠杆。
*   **格式要求**：动词 + 业务影响 + 明确边界。
*   *反面教材*：优化一个图片识别 of AI 模型。（太模糊，无杠杆）
*   *顶级 O*：在极简架构下跑通视觉诊断工作流，利用大模型原生推理能力将传统人工排查摩擦力降低 90%。

### 2. Key Results (关键结果)
KR 必须是**“相互独立、完全穷尽” (MECE)** 的，且极度客观可量化。
*   **KR 1 (核心假设验证 - 极简交付)**：必须在极短的时间盒内验证最难的技术点或商业逻辑。
*   **KR 2 (数据 Grounding - 事实锚定)**：必须有具体的实测数据作支撑。
*   **KR 3 (降级与兜底 - 系统鲁棒性)**：必须设定当高级方案失效时的“笨办法”防线。

## 每日打卡与自我 Debug 协议

在执行本手册时，必须每天进行一次无情的自我 SWOT 诊断，防止滑落回低效模式：
1.  **察觉“工具沉迷” (Threat)**：今天我是否花了超过 2 小时去调整 CLI 工具、MCP 协议或优化 Prompt，而没有产出任何面向用户的真实数据？（如果是，立刻切断 Meta-work，回归单点脚本/核心代码编写）。
2.  **强制“事实复盘” (Weakness 修正)**：每日总结中，是否去掉了所有的“感觉”、“可能”等模糊词汇？是否完全使用“延迟了 200ms”、“许可获取周期长达 6 个月”等微观事实进行陈述？
